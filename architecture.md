# Architecture

The TypeScript entry point in `src/cli.ts` parses commands; `src/interactive.ts` handles guided prompts. `src/adapters/index.ts` selects Linux or macOS. `src/util.ts` runs system commands without a shell and provides the mocked runner used in tests. `src/upgrade.ts` reinstalls the public GitHub package on request. A bundled YAML library edits Netplan documents without an Ubuntu package download at runtime.

Linux backend selection prefers `nmcli`, then `iwctl`, then `wpa_cli`. NetworkManager handles full reads and writes. `iwctl` provides scan/status. `wpa_cli` provides scan/status/list; its SSID parser decodes escaped UTF-8 bytes and ignores invalid entries. When Netplan is present, `src/adapters/netplan.ts` rejects an already configured target, then connects by adding a candidate access point through a 90-second `netplan try`, selecting it in wpa_supplicant, verifying SSID and IPv4, confirming the trial, and copying the candidate into `/etc/netplan` mode 0600. The candidate lives under `/run` and is removed after the attempt. Netplan `try --config-file` also writes a timestamped `.yaml` into `/etc/netplan`; the adapter removes newly generated, content-matching copies after each trial. Forget removes all matching inactive openwifi profile YAML files, including beta.1 escaped-SSID and timestamped copies, and removes matching runtime entries without applying the network configuration. Edit locates one source profile (or identical timestamp duplicates), preserves unrelated YAML settings, validates through `netplan generate --root-dir`, and trials active edits with forced reauthentication before saving. Autoconnect/priority fail closed. `wpa_cli disconnect` is temporary; installed `rfkill` controls radio power. macOS uses `networksetup` and system discovery tools. The build emits a bundled `dist/openwifi.cjs` executable for offline runtime use.
