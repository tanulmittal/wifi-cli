# Project memory

- Public install source is `github:tanulmittal/wifi-cli` with npm `--install-links`; the scoped npm package was intentionally dropped. Normal CLI use downloads nothing; only `openwifi upgrade` needs the network.
- The real test host is Ubuntu 26.04.1 with Netplan + `systemd-networkd` + `wpa_supplicant` on `wlp2s0`, no `rfkill`, and no NetworkManager. The user has physical console access. Never replace its network manager remotely, and do not auto-install Ubuntu tools.
- The user authorized direct SSH testing of that host; do not operate their Termius UI and never store credentials in the repo or logs.
- `wpa_cli` renders UTF-8 SSIDs as `\xHH`, so decode before comparing. A beta.1 trial saved an escaped iPhone SSID; forget now removes both the escaped and literal profile names plus the generated timestamp copies.
- npm treats a Git dependency with an npm `build` script as needing preparation, which collided with the existing global package. Development uses `npm run bundle`; Git installs use the committed `dist/` files and add no lifecycle scripts.
- Pin test installs to an exact commit or tag and compare the installed `dist/openwifi.cjs` SHA-256 with the locally tested bundle before interpreting live results: the global install was once silently replaced with main's 0.1.4.
- iPhone hotspots only appear in scans while the Personal Hotspot screen stays open, and the SSID uses a curly apostrophe. Never start a Netplan trial when the target is absent from a fresh scan.
- The Netplan connect trial must outlive the SSH session that started it: in beta.7 the CLI died with the dropped session, nothing confirmed the trial, and `netplan try --timeout 90` auto-reverted. Beta.9+ runs it in a detached worker (own session, stdio ignored) with state in `/run/openwifi/connect.json`. Verified live: the worker finished 47 seconds after SSH died and `openwifi status` reported the outcome on reconnect.
- A rolled-back `netplan try` restores /etc/netplan and the systemd units but leaves the trial network in two places: the generated `/run/netplan/wpa-<iface>.conf` and the running wpa_supplicant. The worker cleans both during rollback, `doctor` detects either leftover, and `doctor --fix` regenerates the file. `netplan generate` alone did not drop the live WiFi link on this host.
- A hidden commander subcommand must not reuse a program-level global option: `--interface` on the worker was swallowed by the global `--interface`, so every invocation failed with "required option not specified" and, with stdio ignored, the failure was invisible. Worker options are `--iface`, `--ssid`, `--candidate`, and worker output goes to the trial log.
- `openwifi upgrade` must never install the default branch: main is 0.1.4 while the Netplan work is a beta, so the old behaviour silently downgraded the server. It resolves the newest `v*` tag with `git ls-remote` (git 2.53 is installed) and refuses to downgrade without `--force`.
- Releases are GitHub tags, and only tags known to work are kept: v0.1.0 and v0.2.0-beta.10. Version drift is caught by tests/upgrade.test.ts, which asserts src/version.ts, package.json, and the committed bundle agree.
- A saved network can be reselected with `openwifi use <ssid>` (wpa_supplicant `select_network`, or `nmcli connection up`), which writes no configuration. `connect` still refuses to re-trial an already saved SSID and points at `use`.
- Never print `netplan get` output: it contains the WPA password in cleartext. openwifi parses it for key names only.
